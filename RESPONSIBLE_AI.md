# Responsible AI and data handling

- Synthetic data only; import confirmation is a user assertion, not automatic identification of personal data.
- No generative-model calls, API keys or external AI services. Deterministic conditions perform detection; a bounded English parser drafts rules for human approval.
- Every policy finding includes its rule ID/version, wording and recorded data evidence. Missing evidence stays separate from confirmed exceptions.
- A person decides each disposition. Operations submits evidence and compliance verifies closure in the demonstrated workflow. No employee transaction changes automatically.
- Statistical leads cite detector/version and peer evidence. They are investigation prompts, not policy accusations or employee decisions.
- Neutral language and employee clarification/appeal context support fair review. The app does not directly contact employees.
- Imported CSVs, written policies and derived records stay in a device-local vault. Synchronization stops for protected workspaces; server APIs reject them. Keep downloaded backups in approved storage.
- Optional generated-demo server events use server identity, optimistic concurrency and linked hashes. These are prototype controls, not certified or independently anchored audit retention.
- Production use inside Emirates requires internal hosting, real identity and permissions, policy-owner validation, appropriate retention and security review. See the two-page solution note.
